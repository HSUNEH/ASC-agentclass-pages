ASC 에이전트트랙이 강의 목차
LESSON 02 · 2-3

팀은 역할로 나누고,
기준은 함께 씁니다.

에이전트가 각각 다른 일을 해도, 결과 형식과 검증 기준이 다르면 마지막에 합칠 수 없습니다.

이번 레슨이 끝나면각 역할의 입력·할 일·출력과 팀 공통 기준을 분리해 적습니다.

역할은 다르고, 품질 기준은 공유합니다.

리서처는 근거를 모으고, 라이터는 초안을 쓰고, 에디터는 기준에 맞는지 확인할 수 있습니다. 하지만 인용 형식과 최종 파일 규칙은 팀 전체의 약속입니다.

역할

누가 어떤 판단과 작업을 맡는가

스킬

반복되는 형식과 절차를 어떻게 지키는가

공통 기준

모든 결과가 지켜야 하는 검증과 범위

역할 정의는 네 줄이면 시작됩니다.

  • 입력을 적습니다.무엇을 받는지 분명해야 합니다.
  • 할 일을 제한합니다.다른 역할의 일을 중복해서 맡기지 않습니다.
  • 출력 형식을 정합니다.다음 역할이 바로 쓸 수 있어야 합니다.

직접 해봅니다.

<업무 흐름>을 위한 3개 역할을 설계해줘.
각 역할마다 입력, 맡을 일, 출력 형식, 확인 기준을 한 줄씩 적어줘.
공통 기준과 역할별 기준도 구분해줘.

공통 기준은 짧고 직접적으로 둡니다. 긴 배경 자료는 필요한 역할이나 스킬의 참고 파일로 분리합니다.

다음에도 이렇게 판단합니다.

여기까지역할을 잘 나눈 팀은 서로 같은 일을 반복하지 않고, 결과를 합칠 기준도 함께 갖습니다.

원본 강의의 핵심을 더 봅니다.

역할에는 산출물 계약이 필요합니다.

원본 2강은 에이전트마다 목표·입력·출력·도구·모델을 명시합니다. “리서치 담당” 같은 이름만 두지 말고, 출처 URL 목록과 요약처럼 제출할 결과를 정합니다.

지금도 통하는 운영 원칙입니다.

도구 설명도 프롬프트의 일부입니다.

Anthropic은 도구의 인터페이스와 문서를 에이전트 설계의 핵심으로 봅니다. 어떤 도구를 언제 쓰고, 실패하면 무엇을 반환하는지 분명해야 역할이 안정적으로 이어집니다.
