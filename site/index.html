내 컴퓨터에서
Claude Code를 시작합니다.

오늘의 목표는 간단합니다. Claude Code를 내가 정한 작업 폴더에서 실행하고, 정상 동작을 확인한 결과를 파일 하나로 남깁니다.

웹 챗과 무엇이 다를까요?웹 챗은 대화창에서 답을 받습니다. Claude Code는 내가 연 폴더 안에서 파일을 읽고, 만들고, 고치고, 필요한 명령을 실행합니다. 그래서 “답을 써줘”보다 “이 폴더의 메모를 읽고 결정·담당자·기한으로 정리해 파일로 남겨줘”처럼 끝난 상태를 말하는 편이 좋습니다.

여는 곳은 세 군데입니다

터미널, 코드 편집기 안의 터미널, 데스크탑 앱의 Code 화면 중에서 가장 덜 부담스러운 방법을 고르면 됩니다. 어느 화면이 정답인지는 중요하지 않습니다. 내가 의도한 작업 폴더 안에서 여는 것이 중요합니다.

오늘 할 일

  1. 공식 설치 문서 확인운영체제에 맞는 최신 설치 방법을 확인합니다. 설치 방식과 지원 OS는 바뀔 수 있으니, 오래된 화면을 그대로 따라 하지 않습니다.
  2. 설치와 로그인 확인claude --version으로 설치를 확인합니다. 버전 숫자가 다를 수는 있어도, 오류 없이 Claude Code 버전이 나오면 됩니다.
  3. 빈 연습 폴더에서 시작내가 직접 만든 빈 폴더에서 Claude Code를 엽니다. 모르는 프로젝트의 신뢰 확인은 바로 승인하지 않습니다.
  4. 파일 하나 만들기대화창의 답이 아니라 실제 파일이 폴더에 생기는지 확인합니다.
이 폴더에 hello.md 파일을 만들고,
첫 줄에는 "ASC 에이전트 트랙을 시작합니다"라고 적어줘.
파일을 만든 뒤 내용도 확인해줘.

잘된 결과의 기준을
다음 작업에도 남깁니다.

스킬은 AI에게 일을 잘 시키는 긴 프롬프트가 아닙니다. 내가 자주 하는 일을 다시 맡길 수 있게 정리한 업무 안내서입니다.

스킬은 회사의 프리랜서입니다.CLAUDE.md가 프로젝트 전체의 공통 규칙이라면, 스킬은 특정 일이 들어왔을 때 부르는 전문 업무 안내서입니다. 한 번만 할 요청은 대화에 바로 적고, 반복될 일을 스킬로 만듭니다.

스킬은 결과에서 시작합니다

처음부터 완벽한 스킬을 설계하려 하지 마세요. 먼저 한 번 실행해 보고, 결과를 고치면서 다음에도 지키고 싶은 기준을 뽑습니다. 발표자료라면 “제목은 결론부터”, “본문은 세 문장 이하”, “마지막 장에는 다음 행동”처럼 관찰 가능한 기준이 남습니다.

오늘 할 일

  1. 실물을 봅니다공개된 스킬 폴더에서 SKILL.md와 보조 자료 구조를 확인합니다. 언제 쓰는지, 어떤 순서로 일하는지, 무엇을 확인하는지가 핵심입니다.
  2. 계획을 먼저 봅니다실행 전에 입력 파일, 출력 파일, 구성 순서를 보여 달라고 요청합니다. 어디까지 할지 먼저 보면 결과를 고치기 쉽습니다.
  3. 한 번 만들어 보고 고칩니다로컬에 저장한 레퍼런스 파일로 예시 결과를 만들고, 다음에도 지킬 기준을 적습니다.
  4. 내 업무 스킬을 만듭니다이번 달 안에 다시 할 일, 눈에 보이는 결과, 내가 꼭 지키는 기준이 있는 업무 하나를 고릅니다.
  5. 실제로 실행합니다스킬 파일만 만들지 말고, 실제 요청으로 불러 결과를 확인합니다.
내가 반복하는 <업무 이름>을 위한 스킬을 만들어줘.
이 스킬은 <언제 쓰는지>에 사용하고,
결과에는 <반드시 지킬 기준 2~4개>를 지켜줘.
실행 전과 결과를 낸 뒤 확인할 체크리스트를 넣어줘.

정관은 지식창고가 아닙니다.모델이 한 번에 참고할 수 있는 정보와 집중력은 유한합니다. 오래된 메모, 다른 프로젝트 규칙, 한 번만 필요한 설명까지 쌓으면 중요한 기준이 묻힙니다. 반복 업무의 자세한 절차는 스킬로, 긴 참고자료는 별도 문서로 둡니다.

오늘 남길 세 가지

  2. 바꾸면 안 되는 범위인증·데이터 구조처럼 요청 범위를 넘어 쉽게 건드리면 안 되는 영역을 적습니다.
  3. 실행 가능한 검증“꼼꼼히 확인” 대신 테스트·타입 검사·빌드처럼 성공과 실패가 분명한 명령을 적습니다.
# 프로젝트 규칙

## 목적
- 사용자가 할 일을 기록하고 완료 상태를 관리하는 작은 웹앱이다.

## 작업 원칙
- 요청 범위 밖의 인증·데이터 구조는 바꾸지 않는다.
- 기능을 바꾸기 전에 관련 테스트와 현재 동작을 먼저 확인한다.

## 검증
- 변경 뒤 테스트와 타입 검사를 실행한다.

규칙이 행동을 바꾸는지 확인합니다

같은 프로젝트를 두 폴더에 준비합니다. 하나에는 CLAUDE.md가 없고, 하나에만 규칙이 있습니다. 동일한 요청을 실행해 어떤 파일을 바꿨는지, 정해 둔 검증을 실제로 했는지 비교합니다. 규칙이 보이지 않으면 문서를 길게 늘리지 말고 관찰 가능한 한 문장으로 고칩니다.

제출 준비

asc-lesson3-claudemd.txt에 CLAUDE.md, 규칙 없는 기준 출력, 규칙 적용 출력, 검증 결과를 남깁니다. 전후 비교의 정확한 실행 명령은 현재 Claude Code 환경에서 재현한 뒤 교육 플랫폼에 확정합니다.
